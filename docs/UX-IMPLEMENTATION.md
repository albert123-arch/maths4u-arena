# Каталог, самостоятельная практика и проверка вложений

База разработки: коммит `9fa05c01e95591357f99547fa35ed3c789b94571`. Изменения подготовлены в `codex/learning-review-ux`; эта ветка запускает только проверку GitHub Actions. Hostinger продолжает получать production из `main`. Настройки рабочего запуска не меняются: Other, Node.js 22.x, root `./`, `npm run build`, output `dist`, entry `server.js`.

- Просмотрщик фото и многостраничного PDF встроен в проверку. PDF.js и worker одной версии размещены локально. Никакие ответы не отправляются внешним просмотрщикам. Все варианты файла проходят одну проверку доступа.

Обработка: максимум 2 активных задания, 4 ожидающих, ограничение потоков libvips, таймауты; preview PNG до 2560 px без увеличения и thumbnail до 240 px, EXIF учитывается. Производные не списывают квоту пользователя второй раз.
- Замена/удаление вложений сериализованы с изменением попытки. Удалённые записи остаются как tombstone; файловые остатки можно повторно очистить через закрытый кабинет администратора. Старые файлы не конвертируются при старте и остаются доступны.

Добавлены закреплённые `sharp 0.35.4` и `pdfjs-dist 6.3.289`. Остальные прямые зависимости не обновлялись. Требуется Node.js **22.13+ в ветке 22**. Для HTTP API сохранены авторизация, проверка Origin, политики работы и закрытое хранилище.

## Исправление уже опубликованного пилота

Не импортировать заново ZIP старого пилота. Исправление применяется только к новым версиям задач. Снимки существующих работ, ответы и оценки сохраняются с прежним содержимым.

1. Сохранённый исходный пакет `.local/content-pilot/bundle.json` и его исходные HTML являются неизменяемой базой сравнения. `node scripts/pilot/prepare-correction.mjs` проверяет SHA256 источников и локальной метаинформации, выделяет DOM-блоки `sol-ID` и `mk-ID`, связывает изображения с существующими ID файлов. Старые проекты читаются, но не изменяются.
2. Результат — `.local/content-pilot-correction/correction.json`. Проверенная контрольная сумма JSON-представления: `d2a6c900804fa561e8ef1e2a79e9c14c5c00628ba8ce6de1431a191f7fbf8cb3`. Пакет остаётся вне Git и сборки.
3. После выпуска кода войти администратором на `/admin/import`, выбрать этот JSON в блоке исправления, выполнить **dry-run**. План должен показать 36 новых версий maths4u, одну новую версию олимпийской темы с EN/RU и **0 новых файлов**. 36 MS-изображений получают новую роль, ещё одно изображение условия остаётся на месте; всего по-прежнему 37 файлов пилота.
4. Проверить план и применить. При несовпадении исходных ID, порядка, старого текста, хеша или файла операция останавливается. Параллельное изменение проверяется по fingerprint и блокировкам.
5. Повторный dry-run и применение должны давать unchanged: новых версий и файлов нет. Старый v1-пакет после исправления запрещён; обычный импорт не перезаписывает привязанные к пилоту задачи.

Все 36 текущих задач maths4u имеют отдельный текст подробного решения и MS. Возможность иметь только MS проверяется отдельной синтетической задачей. В источнике Tangents and normals нет текста теории; он не генерируется. Олимпийская теория и 8 примеров разделены по исходным DOM-секциям, обе локализации сохранены. Контроль количества формул до/после разделения проверяется тестом.

Новый обычный `pilot:prepare` создаёт v2 в `.local/content-pilot-v2`; перезапись сохранённого v1-пакета запрещена. Этот v2 не разрешён автоматически к публикации маршрутом старого хешированного ZIP. Для действующей Arena используется только проверяемое исправление выше.

## Повторение локальных проверок

Нужны Node.js 22, установленная локальная Arena MariaDB на loopback и сохранённые исходные файлы пилота. Секреты берутся из приватных локальных файлов; команды их не печатают.

```powershell
node scripts/pilot/prepare-correction.mjs
node scripts/pilot/run-local.mjs --ux
node scripts/ux-preview.mjs
```

`--ux` создаёт новую изолированную `maths4u_test_pilot_*`, применяет миграции и последовательно проверяет исправление/вложения, каталог на 124 задачах (120 доступных), самостоятельную практику и редактор структуры. Ничего не сбрасывает. Адрес просмотра: `http://127.0.0.1:3102/courses`. Тестовые учитель/ученик/администратор и пароль находятся **только** в `.local/content-pilot-correction/preview.json`.

При работающем preview, во втором терминале:

```powershell
node node_modules/@playwright/test/cli.js test --config=playwright.ux.config.ts
```

Браузерный сценарий использует установленный Edge. Снимки desktop/mobile остаются в `.local/content-pilot-correction/`. Подготовка новой UX-базы меняет только приватную конфигурацию preview; перед ней остановите прежний preview, затем запустите заново.

Остальные проверки:

```powershell
npm run typecheck
npm run lint
npm test
node scripts/pilot/run-local.mjs
node scripts/pilot/run-local.mjs --publication
$env:PILOT_LOCAL_TEST = '1'
node --import tsx --test tests/pilot-migration.test.ts
node --import tsx --test tests/hostinger-diagnostics.test.ts tests/hostinger-runtime.test.ts tests/image-previews.test.ts
npm run build
```

`pilot-migration` сначала устанавливает только исходную 001, создаёт непустую базу с оценкой, затем применяет все миграции и повторяет их. Сравниваются хеши всех прежних колонок всех таблиц, а не только количества строк. Дополнительно проверяется самостоятельная практика на обновлённой схеме.

Команды Prisma generate/typegen/build и Next dev выполняются последовательно, не одновременно. `pilot:test`/`--publication` создают собственные базы и меняют runtime preview; для итогового предпросмотра последним выполняйте `--ux`.

## Linux и выпуск

Workflow `.github/workflows/hostinger-preview.yml` проверяет Ubuntu / Node.js 22 / MySQL 8.4 без production-секретов: npm ci, lint, TypeScript, миграцию непустой базы, native Sharp, сборку и запуск упакованного приложения в **hbuilds/current/nodejs/dist**. Проверяет удержание блокировки миграций, ранний listen за 3 секунды, HTTP 503 до готовности, применение всех миграций, вход первого администратора, повторный деплой, сохранность администратора/данных/файла и SHA256, восстановление права исполнения Prisma engine. Успех конкретного запуска нужно смотреть по SHA; наличие workflow само по себе не является результатом проверки.

Перед переносом изменений в `main` сделать **новые** резервные копии рабочей базы и всей текущей приватной папки: копия одного storage-probe, сделанная до загрузки 37 файлов пилота, для этого выпуска недостаточна. Проверить доступность восстановления. Не заменять production локальной базой.

После деплоя проверить runtime, `/api/health`, вход администратора и ученика, текущие аккаунты/роли/пароли/попытки/оценки; затем выполнить исправление пилота через авторизованный кабинет. Проверить 36+20 задач, 37 файлов, порядок, формулы/EN-RU, просмотр фото/PDF и повторный dry-run. Существующие опубликованные работы намеренно сохраняют прежние версии.

`npm run build` по-прежнему создаёт `dist`, подключение к рабочей БД во время сборки не требуется. Runtime применяет сохраняющие данные миграции перед открытием рабочих API. Параметры Hostinger `MATHS4U_ENV`, `MATHS4U_DATABASE_URL`, `MATHS4U_DATABASE_NAME`, `APP_URL`, `PRIVATE_STORAGE_PATH` и рабочий порт не заменяются локальными. Новый необязательный параметр **MATHS4U_MAX_IMAGE_PIXELS**: 40000000 по умолчанию, допустимо от 1000000 до 80000000.

Управление местом доступно в `/admin/import`; npm через SSH не нужен. Для локального обслуживания имеется `node --import tsx scripts/storage-maintenance.ts --audit` и `--retry-deleted`; это не инструкция для SSH Hostinger, где npm недоступен. Сканируются только зарегистрированные ключи файлов Arena, без обхода соседних каталогов.

## Границы выполненной проверки

Локально проверены настоящий пилот, совпадение 37 изображений по SHA256, неизменность старых попыток/оценок, повторное исправление, API-доступы, ограничения/гонки загрузки, EXIF, PDF, набор из двух тем через пагинацию, сохранение/проверка/самопроверка и RU/EN на 390×844.

Предпросмотр проверен на реальных MS и синтетическом математическом скане. **Реальную фотографию мелкого рукописного решения с телефона владелец пока не предоставлял**: предел 40 Мп, масштаб 2560 px и читаемость такого почерка требуют отдельной проверки на этих файлах. Новые UX-изменения и исправление версий пилота в рамках этой локальной подготовки на Hostinger не применялись. Результат Linux CI фиксируется отдельно в итоговом сообщении. Успех сборки не означает проверку входа или файлов на рабочем сайте.

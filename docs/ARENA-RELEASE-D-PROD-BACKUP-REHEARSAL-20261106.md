## Как воспроизведён Hostinger и что показали проверки

Применялись настоящий runtime пакета, Node 22.23.4, production-mode, HTTPS APP_URL Arena, readiness gate, migration lock, `prisma migrate deploy`, сохранение существующего администратора и автоматический runtime-импорт. Только адрес подключения заменён на новую loopback-базу, PORT — 3108, PRIVATE_STORAGE_PATH — новый пустой локальный приватный каталог. Bootstrap администратора отключён.

1. Восстановлен полный экспорт без изменения значений данных. Выполнены baseline, проверка FK, источников и количества миграций.
2. Первый Windows-старт остановился до миграций на проверке checksum. Причина установлена: семь из десяти старых SQL-файлов в Windows checkout/artifact имеют CRLF, а production checksum соответствует LF-файлам в Git. **Все десять production checksum совпали с точными Git blobs.** Данные и `_prisma_migrations` не правились.
3. Только в игнорируемом `dist/prisma/migrations` все 14 файлов сверены и записаны точными байтами Git — такими, какие получит Linux checkout Hostinger. Десять файлов отличались только окончаниями строк: семь старых и три новых. Рабочие исходники и Git не менялись. Проверка checksum не отключалась.
4. Повторён тот же production-entry. Новые четыре миграции применились, существующий администратор сохранён, 516 задач импортированы одной транзакцией. Ручного запуска импорта/SQL-разметки не было.
5. Во время успешного старта собрано 112 HTTP-наблюдений: только 503, затем 200 с total=688. Пустого каталога или выдачи Cambridge не наблюдалось. До подключения к БД процесс готовности выдаёт только 503.
6. Проверены все страницы каталогов четырёх ролей и точные разрешённые ID; скрытые курсы дают настоящий 404. Проверены доступ к презентациям и реальная старая попытка ученика. Вход проверялся только локальными тестовыми Session, исходные пароли не вводились и не менялись.
7. Сервер перезапущен без `ARENA_RELEASE_D_APPLY` и `ARENA_RELEASE_D_BACKUP_ID`. Снова готов, 688 видимых задач; повторного импорта нет. Полные снимки **всех 62 таблиц** непосредственно перед и после этого перезапуска идентичны.
8. Финально повторена сверка исходных строк и FK. После проверки остановлен только новый сервер PORT 3108; другие локальные серверы и базы не останавливались.

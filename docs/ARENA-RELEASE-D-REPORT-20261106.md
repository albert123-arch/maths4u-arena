# Arena — подготовка полного релиза D, 6 ноября 2026

## 1. Что сделано и почему

Подготовка выполняется только в `D:\www\arena`, репозиторий `maths4u-arena`, целевой адрес `https://arena.maths4u.sbs`. Проект PHP `maths4u.sbs`, его файлы и база не использовались. Рабочая база Arena не открывалась. Push и deploy не выполняются.

Требования владельца перенесены в раздел «Деплой → D» [дорожной карты](CODEX-ARENA-ROADMAP-20261105.md). Отдельный файл плана теперь указывает на этот единственный актуальный раздел.

Слияние H1 с Этапами 1–6b совмещает две проверки: происхождение/обратимый архив и точный запрет H1 по `Cambridge` / `Cambridge International` в любой исторической версии. Категория EXAM не используется как признак чужого авторства. Ручное снятие архивной отметки не отключает H1. В истории D сохраняет собственный ответ и балл ученика, отдавая вместо условия безопасную заглушку; H1-ограничения на новые работы, файлы и редактирование остаются.

Разметка существующих материалов добавлена **новой** миграцией `20261106160000_release_d_provenance`. Старые миграции и checksum не меняются. Предыдущие отметки всех Task сохраняются в `ContentReleaseTaskBackup`. Book 2 размечается по подтверждённым `ImportRecord(sourceProject='olymp', legacyId=493…512)` и кодам `NT-B2-M01-P001…020`, а не по локальным Task ID.

Новый runtime-coordinator использует общий исправленный writer импортёров. Он добавляет 516 авторских задач (100 written + 208 short + 208 fresh), конспекты и связи, затем одобряет только точные идентичности проверенного пакета. Общие импорты по-прежнему оставляют неизвестное в карантине, а Cambridge сразу архивируют. Публичного API запуска релиза нет.

**Без окна раскрытия/пустого каталога:** старый H1 не зависит от новых полей и продолжает запрещать Cambridge; новый процесс не открывает Next.js до миграций, сверки и завершения транзакции. До готовности все маршруты возвращают 503. Это штатная пауза запуска, а не гарантия непрерывной доступности. Если состав базы не совпадает с планом, новый процесс остаётся закрыт и завершается.

Перед транзакцией сохраняется приватный SELECT-план с fingerprint и ссылкой на резервную копию. Маркер `ContentRelease(APPLIED)` пишется **в той же транзакции**, что импорт. Повторный запуск и авария после commit не создают дубликаты. Ключи, баллы, критерии, старые TaskVersion, попытки и оценки не перезаписываются.

### E. Откат без потери новых ответов

Подготовлена локальная ветка `rollback/release-d-h1-compatible`: старый интерфейс H1 с **полной новой схемой/миграциями** и дополнительным запретом Demo/UNKNOWN. Учительское редактирование задач в аварийном интерфейсе временно только администратору. Архивные попытки снова закрыты целиком, как в H1, но строки ответов/оценок сохраняются. Новые интерфейсные возможности D временно отсутствуют.

Не нажимать старый неизменённый H1 deployment в hPanel: он отвергнет новую историю миграций. Не делать reset/force и не восстанавливать старую БД поверх появившихся ответов.

После отдельного решения об откате проверить, что origin/main равен **точному принятому SHA релиза D**. Если после него есть другие коммиты — остановиться и подготовить новый совместимый recovery. Из подготовленного проверенного дерева создать новый обычный коммит с родителем текущего принятого D, без изменения локальной main:

```powershell
Set-Location 'D:\www\arena'
git diff --quiet
if ($LASTEXITCODE -ne 0) { throw 'Есть изменения' }
git diff --cached --quiet
if ($LASTEXITCODE -ne 0) { throw 'Есть изменения в индексе' }
git fetch origin main
if ($LASTEXITCODE -ne 0) { throw 'Fetch не выполнен' }
# Сверить origin/main с записанным при успешном деплое SHA D. Иначе СТОП.
$deployed = git rev-parse origin/main
$tree = git rev-parse 'rollback/release-d-h1-compatible^{tree}'
if ($LASTEXITCODE -ne 0) { throw 'Проверенное recovery-дерево отсутствует' }
$recovery = git commit-tree $tree -p $deployed -m 'Restore H1 interface with Release D database safeguards'
if ($LASTEXITCODE -ne 0) { throw 'Recovery commit не создан' }
git push origin "${recovery}:main"
```

Этот push — **будущая отдельная операция владельца**, не часть подготовки. База, миграции, авторские импорты и новые ответы при ней не откатываются. После автодеплоя повторить health, все страницы каталога, запреты и сохранность данных. Для изменения ошибочных данных использовать приватный журнал и отдельный reviewed append-only план; полное восстановление backup допустимо только при доказанном отсутствии более новых данных либо после их сохранения/сведения.

## 6. Ограничения и подтверждение

- Репетиция соответствует согласованному составу, но не подтверждает неизменность production после H1. Runtime останавливается на расхождении; это не повод ослаблять проверки.
- Не проводилась независимая новая редакторская проверка всей математики; прежние pending/DRAFT не подменяются статусом verified. Очищаются только ранее согласованные служебные фрагменты.
- Производительность на Hostinger, TLS и Linux CI нового коммита требуют будущего разрешённого preview/deploy. Локальные проверки их не заменяют.
- Старые `.local` журналы/тестовые базы, output/ и tmp/ сохранены. Отдельное приложение или копия проекта не создавались.
- **Без push, deploy, подключения/изменения production-базы, реальных вызовов ИИ, внешней аналитики, рекламы и платежей. Этап 7 не начат. После отчёта работа останавливается.**

## Исправления до main

Найдено взаимодействие нового personal authoring с прежним кабинетом ученика:
задание с PRIVATE Task без публичного LessonTask могло отсутствовать на главной
ученика, вместе с отзывом преподавателя. Теперь карточки и отзывы берутся из
уже авторизованных `listWorks(actor)` независимо от выбранного публичного курса.
Сохранены userId, USER-lens, maySeeResult и архивные ограничения **всех версий**
работы. Личные задания не прибавляются к публичной аналитике курса/readiness.

15 model tests прошли; отдельная реальная проверка на изолированной базе —
7 сценариев / 25 assertions: отсутствие CourseFollow, ручная публикация,
отзывы и 4/4, изоляция учителей, UNKNOWN и исторический Cambridge.
Два файла новой логики/тестов вошли в окончательные 101 файла. Весь окончательный
SHA повторно прошёл полный Linux CI.

Нормализованы только хвостовые пробелы копируемой лицензии MathLive, без изменения
лицензионного текста. Локальный общий eslint первоначально захватил посторонние
output/tmp; эти каталоги не отправлялись. Чистый Linux checkout прошёл штатный
полный lint без исключений.

## Реальные проверки сайта

Использованы только два новых явно синтетических QA-аккаунта, свой QA-класс,
своя личная задача, работа и попытка. Работы настоящих учеников не открывались
для изменения и не оценивались.

1. Саморегистрация teacher/student прошла, роли и ограничения 3/100 прочитаны
   обратно из API. Для нового teacher административные API — 403. Все 33 lesson
   IDs, содержащие 59 архивных презентаций, возвращают teacher 404. Пустой список
   презентаций опубликованного урока возвращает 200 с items:[] — это не утечка.
2. Визуальный ввод настоящей дроби через MathLive, редактируемая формула,
   safe-preview, private save и submit прошли. До одобрения у гостя задачи нет.
   20 локальных font URL дают 200. Редактор и кабинет учителя: 8 состояний.
3. Поданный V1: одна часть, 2 marks, точный ответ 3. После отправки создан
   PRIVATE V2: две части, 4 marks, расширенное объяснение. В homework назначен V2;
   ученик отправил ответы, учитель открыл новый review screen, переключал решение /
   критерии, подтвердил баллы и опубликовал результат. Получены 4/4, отзыв в кабинете
   ученика и запись в прогрессе класса. До ручного release результат был скрыт.
   Экран проверки — 4 состояния без ошибок.
4. Ученик с сохранённым ru-профилем видит английский документ/интерфейс.
   Dashboard / Review / Notebook — 12 состояний; бесплатный доступ и ограничения
   аналитики/ИИ соблюдены.
5. Через настоящий owner UI проверены V1, ответ и M1/A1; видна пометка о новом
   личном V2. Одобрен именно V1. Гость получил отдельный публичный Task с одной
   частью и исходным заголовком. Личный V2 и назначенный V2/результат 4/4 остались
   прежними. Снимок teacher-approved-1280-light.png показывает Approved +
   Newer private changes.
6. Новый QA-ученик через Report an error отправил OTHER только для новой публичной
   копии. В админке проверены точные public task/version IDs и сообщение; report
   переведён в RESOLVED, revision 1. Условия, ответы, баллы не менялись.
7. Гостевые home/register: 8 состояний 390/1280 × light/dark. Ноль page/React/KaTeX
   ошибок и горизонтальных переполнений. MathLive JS/шрифты не грузятся на публичной
   главной; внешних запросов и попыток записи в read-only smoke не было.

В сценариях явно ожидалась готовность account context и cold lazy editor. Две
первоначальные остановки harness были селекторами закрытой карточки / guest SSR
до гидратации; после чтения фактической формы ожидание исправлено, приложение не
менялось. Реальные успешные POST и readback сохранены отдельно от диагностики.

# Пилот: maths4u 576 и olymp NT-B2-M01

Пилот подготовлен и просмотрен локально 13 сентября 2026. Публикация разрешена владельцем. Этот документ описывает проверенный пакет и порядок публикации; сам по себе он не подтверждает успешный production-импорт.

## Состав

| Источник | Структура | Содержимое |
| --- | --- | --- |
| [maths4u, subchapter 576](https://maths4u.sbs/subchapter.php?id=576) | Additional Mathematics / Cambridge 0606 → Calculus - Differentiation 1 (chapter 117) → Tangents and normals | 36 задач EN, условия и решения; 1 рисунок условия и 36 изображений схем оценивания |
| [olymp, Advanced GCD Problems](https://olymp.maths4u.sbs/courses/number-theory2/chapters/book2-module1-advanced-gcd-problems/practice?lang=en) | Book 2. Olympiad Number Theory Methods → Advanced GCD Problems → теория и практика | 20 задач с RU/EN, подсказками и решениями; теория и 8 разобранных примеров на каждом языке |

Всего: 56 задач, 76 языковых версий задач, 3 языковые записи теории/раздела (в maths4u тело теории пустое), 37 PNG (5 620 764 байта), 1 788 формул. В выбранных разделах SVG не найдено; поддержка форматов файлов не расширялась.

Сайты читались HTTP GET, без подключения к старым базам или выполнения SQL. Для maths4u использованы текущие страницы и ограниченная выборка из club-import-work/existing-problems.json: все 36 условий и решений совпали после извлечения исходных HTML-фрагментов. Медиа загружены с текущего сайта; их SHA256 записан в пакете. Актуальный модуль olymp в локальных SQL не найден, поэтому использованы опубликованные страницы EN/RU, включая скрытые в интерфейсе, но присутствующие в HTML подсказки и решения.

## Артефакты

Все реальные данные находятся в игнорируемом Git каталоге .local/content-pilot:

- bundle.json — переносимый пакет с исходными ID/URL, путями разделов, порядком, переводами, метаданными и картой файлов;
- assets/ — 37 PNG с именами по SHA256;
- audit.json — счётчики и сравнение maths4u с локальным снимком;
- import-result.json — карта ID Arena и результаты проверенного первого импорта;
- preview.html и katex/ — автономный предпросмотр с тем же renderContent, который использует Arena;
- maths4u-pilot.zip — пакет и предпросмотр без секретов, исходных HTML-страниц, тестовых данных и реквизитов базы.

runtime.json содержит только приватные реквизиты отдельной локальной тестовой базы. Он не входит в ZIP, Git, предпросмотр или dist. Каталоги source/, storage/ и checks/ также не включаются в переносимый архив.

## Изменения Arena

Добавлена таблица LessonTask с порядком задач внутри урока. Исходные production-миграции не менялись; новая миграция только создаёт эту таблицу. Выбранная структура представима как Course → Topic → Lesson → упорядоченные задачи, без потери уровней выбранных разделов.

В странице курсов отображаются название темы и ссылки на задачи урока в исходном порядке. Поиск банка задач принимает начальный параметр q из ссылки. Изображения в тексте больше не дублируются как отдельные вложения; выбирается соответствующий язык вложения.

Файлы импортируются в приватное хранилище, ссылки заменяются на /api/files/<id>, а роли STATEMENT/SOLUTION сохраняются. Схемы оценивания остаются частью решения. Полные исходные тексты хранятся в версиях, без перефразирования и перевода.

Импортёр scripts/pilot/import.ts намеренно работает только при MATHS4U_ENV=test, на 127.0.0.1, с именем базы maths4u_test_pilot_* и хранилищем внутри .local/content-pilot/storage. Материалы локального импорта создаются PRIVATE, курсы не публикуются. Перенос на Hostinger этим локальным скриптом запрещён программно. Для production используется общий импортёр через авторизованный административный интерфейс, описанный ниже.

## Проверки

Под Node.js 22.23.2 / Windows прошли 6 пилотных тестов и 21 проверка существующего API. TypeScript и ESLint прошли. Production-сборка и проверка артефакта выполнены отдельно; Linux в рамках этого пилота не запускался.

Проверены: 56 задач / 76 переводов / 37 файлов / 2 курса / 2 темы / 2 урока; точное равенство текстов; порядок 56 связей LessonTask; хеши сохранённых изображений; повторный импорт без новых задач, файлов и версий; сохранение администратора; новая редакция одной изменённой задачи и сохранность старой; отказ при повреждённом файле; доступ администратора и отказ посетителю/ученику для закрытых материалов. Временная правка теста восстановлена обычной новой редакцией, без reset/drop.

Все 1 788 формул прошли разбор KaTeX с throwOnError=true, trust=false и ограничениями раскрытия макросов. Дополнительно проверен реальный renderContent Arena. В браузере проверены образцы EN/RU, теория, рисунок условия, раскрытие решений, загрузка всех 37 изображений и отсутствие katex-error. Это проверка переноса и отображения, не математическая перепроверка каждого исходного решения.

## Повторение

В корне Arena с Node.js 22 и установленными зависимостями:

1. npm run pilot:prepare — прочитать сохранённые страницы (или скачать отсутствующие), собрать пакет и изображения. Для нового снимка: npm run pilot:prepare -- --refresh. Нужны читаемые локальные метаданные maths4u по пути, указанному в скрипте.
2. npm run pilot:test — создать новую отдельную локальную тестовую базу, применить миграции, проверить первый и повторный импорт. Использует уже настроенный локальный сервер Arena на порту 33317 и .local/db-secrets.json; старые проекты не читает и не меняет.
3. npm run pilot:preview — пересобрать автономный предпросмотр.
4. npm run pilot:serve — открыть http://127.0.0.1:3101. Сервер слушает только loopback и отдаёт только preview.html, PNG и шрифты/CSS KaTeX; остальные файлы закрыты.

При неудачном импорте транзакция не оставляет частичных строк базы. Из-за отдельного файлового хранилища прерванная транзакция может оставить непривязанный приватный файл; автоматическое удаление ранее перенесённых файлов не выполняется.

## Публикация на Hostinger

Одобренный ZIP: `.local/content-pilot/maths4u-pilot.zip`, SHA256 `9c4adfa6a1fdca521fd82d27f92559cb7265937f9a36018359b77fd7c1c636f2`.
Хеш `JSON.stringify(JSON.parse(bundle.json))`: `9bb8f7ce308223af6e3a7a7a92d0032c78a572d01926fcd3a1b2c19ece156db5`.
Не обновлять снимок источников перед публикацией: сервер принимает только этот проверенный пакет.

1. До push в main создать свежую резервную копию `u770916388_arena` в hPanel → Backups, проверить дату, выбранную базу и доступность Download/Restore. Восстановление сейчас не запускать. Общая копия сайта может охватывать только public_html: приватное хранилище копируется отдельно.
2. В настройках именно Arena прочитать PRIVATE_STORAGE_PATH. В текущих проверенных настройках это `/home/u770916388/private/`. Сделать отдельный архив содержимого этого каталога, включая скрытый файл storage probe, вне private, hbuilds и public_html; проверить список файлов архива, размеры/хеши и доступность скачивания. Никакие каталоги других сайтов не архивировать и не восстанавливать.
3. Запустить `PILOT_LOCAL_TEST=1` и `node --import tsx --test tests/pilot-migration.test.ts` на Node.js 22. PowerShell: `$env:PILOT_LOCAL_TEST='1'`. Тест создаёт новую loopback-базу, разворачивает только исходную миграцию, добавляет пользователей, задачу, работу, попытку, ответ и оценку, затем применяет новую миграцию обычным migrate deploy дважды и сравнивает хеш каждой старой строки. Reset/drop/db push не используются.
4. Проверить `npm run pilot:test` и `node scripts/pilot/run-local.mjs --publication`. Второй запуск создаёт ещё одну отдельную базу и проверяет точный пакет через те же административные API: 56 задач, 76 переводов, 37 изображений, повтор без новых версий, сохранение аккаунтов, закрытые решения, запрет чужого origin и постороннего пакета.
5. Сначала проверить коммит в hostinger-preview: workflow Hostinger preview package запускает Linux/Node.js 22, миграцию на непустой базе, сборку без production-настроек и тест готового dist в структуре hbuilds/current/nodejs/dist. В main отправлять этот же проверенный коммит fast-forward без force push только после подтверждения резервных копий.
6. Настройки hPanel сохраняются: Other; main; Node 22.x; root `./`; build `npm run build`; output `dist`; entry `server.js`. Сборка не соединяется с рабочей базой. При старте выполняются существующие миграции; SHA256 engine проверяется до восстановления права исполнения; рабочие API открываются после готовности базы. Настройки администратора и хранилища не менять.
7. После успешного деплоя войти администратором в `/admin/import`, раскрыть ZIP локально и в блоке «Публикация проверенного пилота» выбрать `bundle.json` и все PNG из `assets/`. Нажать «Проверить и опубликовать пилот». npm/CLI на SSH не требуется.
8. Файлы загружаются отдельно, с проверкой SHA256, и остаются приватными. До загрузки всех 37 файлов материалы не публикуются. Затем одна транзакция сохраняет структуру, порядок, переводы и открывает учебные курсы/условия. Решения и схемы оценивания сохраняют прежние правила доступа. При конфликте с существующими импортированными задачами или курсом первая публикация прекращается, не перезаписывая их.
9. Повторить тот же пакет: ожидается `created=0`, `updated=0`, `skipped=56`, без новых файлов и версий. Прерванную загрузку можно повторить: уже проверенные файлы пропускаются. В БД остаётся событие PILOT_PUBLISHED с хешем пакета.
10. Проверить `/api/health`, вход администратора, оба курса на RU/EN, порядок задач, формулы и изображения, мобильное отображение и обязательную авторизацию для начала практики. Сравнить существующие строки базы/файлы с резервной копией; учитывать отдельно новые материалы, сессии и проверочные учебные попытки.

Административные POST `/api/admin/import/pilot/check`, `/asset`, `/publish` находятся под существующей проверкой сессии ADMIN и same-origin. Они не создают администраторов, не выполняют SQL из пакета и не принимают произвольные пути, URL скачивания или другой пакет. Production разрешён только при явном MATHS4U_ENV=production, базе u770916388_arena и APP_URL=https://arena.maths4u.sbs. Локальный режим разрешён только на отдельной тестовой базе.

После успешного импорта ссылки: `/courses/maths4u-0606` и `/courses/olymp-number-theory2`. Наличие этих маршрутов до импорта не означает наличия материалов.

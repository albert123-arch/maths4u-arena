# Arena search and traffic growth

## Public baseline, 22 November 2026

The audit parsed the entire live [sitemap](https://arena.maths4u.sbs/sitemap.xml) and made 51 representative guest GET requests across the directory, every course, selected chapters and lessons, Russian equivalents, query states and invalid paths. All 872 sitemap locations were unique, on the Arena origin and free of queries or fragments. They comprise 4 standalone pages, 6 English level pages, 14 English course roots, 140 chapters, 705 English lessons and 3 Russian pages. This measures the sitemap inventory. Search Console determines how many URLs Google has indexed.

- `/robots.txt` and `/api/health` returned HTTP 200. Robots listed the public sitemap and excluded named account, admin and API paths. The search results and printed lesson revision sample served `noindex, follow`. The completing-the-square page retained its query-free canonical with `mode=MC`, `mode=SHORT`, `mode=WRITTEN`, `practice=previous`, `view=revision`, `view=legacy` and `utm_source` separately.
- Sampled study packages exposed breadcrumb and learning-resource JSON-LD. Directory structured data described the website and programme collections. Keep the existing markup aligned with visible content and verify it by type. Treat rich-result eligibility as a separate Google check.
- The successful sampled responses each had one H1. The arbitrary `/for-teachers/audit-missing` suffix returned HTTP 200 and H1 `404`. The same suffix on `/library` or a legacy topic returned duplicate content with a self-canonical. The legacy lesson “Advanced GCD Problems” also self-canonicalised under both `/courses/maths4u-9709-p1/topics/…` and an invented course slug. The local implementation rejects unsupported route shapes with 404 and redirects public legacy aliases to their owning course with their query state. The public visibility check runs before the redirect. [Google Search Central on canonical signals](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls)
- Public metadata had `og:title` and no `og:image` throughout the sample. The local implementation provides a 1200 × 630 Arena share card, route-specific directory descriptions and existing course descriptions where available. The `0606` course title now uses its displayed syllabus code. Search now puts named papers and syllabus-code matches above lessons that merely share that course context.
- One network sample from this workstation gave a median response first byte of 1.63 s across 51 routes and individual first bytes of 3.10 s for `/courses` and 3.39 s for `/library`. The local implementation removes the full discovery index lookup for static directory metadata and skips translation lookup for route shapes that cannot have a Russian counterpart. The public PageSpeed API returned HTTP 429, so this audit has no verified field Core Web Vitals. Capture the mobile p75 for LCP, INP and CLS where Search Console or CrUX has data. The good thresholds are 2.5 s, 200 ms and 0.1 respectively. Keep repeatable cold-cache mobile lab runs separate from field data and this mixed-route network sample. [Google Search Central on Core Web Vitals](https://developers.google.com/search/docs/appearance/core-web-vitals)

On the isolated preview, the original legacy topic returned 200, the wrong-course alias redirected with 308 while retaining the mode and repeated query keys, and four unsupported or missing routes returned 404. The local sitemap matched all 872 current live URLs exactly. All three local Russian URLs retained their self-canonical and English alternate. Seven focused unit tests and three Playwright tests passed, including search ranking at 390 and 1280 px, no horizontal overflow, and the revision canonical, robots directives and share-image metadata. The repeatable checks are in `tests/discovery-levels.test.ts`, `tests/further-seo.test.ts` and `tests/ux-browser/public-discovery-seo.spec.ts`.

Two paired discovery reads on the isolated rehearsal database returned identical ordered records covering 14 courses and 705 visible lessons. Removing the duplicate course-level visibility predicate reduced query time from 57,030 to 343 ms and 42,104 to 299 ms in those samples. Course eligibility is derived from the same selected lessons and receives no additional caching. The translation task query reduced 28,732 rows to 20 by selecting rows with Russian statement or prompt candidates, then grouping once by lesson. The task retrieval and grouping sample went from 537 to 352 ms. All existing Russian lesson, course and direction eligibility matched exactly. These measurements describe local query work.

## Content acquisition

Use the existing lesson and chapter URLs to answer specific searches. Start with six mathematically verified lessons drawn from 0580 function graphs and bounds, 9709 completing the square and normal distribution, and 9231 polynomial roots and matrices. Confirm the corresponding public canonical per lesson before building each cohort. Use a comparable unchanged lesson per treatment lesson. Use Search Console query data to choose the exact titles and order after the baseline instead of assuming demand.

Each selected page should make its syllabus skill immediately clear, teach it, give an original worked example, offer a short checked question and hand back to the related chapter or next skill. Include previous knowledge where it changes the explanation. Provide an A4 revision sheet or original teacher set only if it adds a real classroom activity, exact answers and an accessible HTML entry point. Keep notation in KaTeX and keep figures for visual reasoning. Pilot two short original videos on already verified pages. Link from the video description to the corresponding lesson and defer loading the player until the learner clicks. Use links from chapters and course directories to their matching lessons. Keep practice states and print variations on their existing canonical lesson. [Google Search Central on sitemaps](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap)

Use the same published pages for Google Search's AI features. Put the definition, formula, relevant conditions and original derivation in crawlable HTML with descriptive nearby text. The structured data should represent the visible page. Include these pages in the ordinary Search Console cohort. [Google Search Central on AI features](https://developers.google.com/search/docs/appearance/ai-features)

Reference approaches examined were Save My Exams for worked-example sequencing, Physics & Maths Tutor for discoverable resources by topic, Dr Frost for independent practice and rounds of mastery, and Khan Academy for revisiting more than one skill. ## Measurement and 90-day experiments

Use the Arena URL-prefix property in Search Console or filter the domain property by `https://arena.maths4u.sbs/`. Preserve the separately scoped numbers for the main site and any other subdomain. For each cohort record canonical URL, launch date, programme, query family, device, organic impressions, clicks and CTR. Export the preceding 28 complete days as the baseline, exclude recent partial reporting days and compare equal periods with the same device and query filters. Segment branded queries because changes in their share can move CTR. Compare position per query to help interpret snippet tests. Search Console data was unavailable in this guest audit. [Search Console Performance report](https://support.google.com/webmasters/answer/7576553)

| Days | Experiment | Measure and decision |
| --- | --- | --- |
| 1–14 | Confirm valid sitemap pages, inspect Google-selected canonical on the six candidates and a representative language pair, verify mobile render and key learning tasks. | Record sitemap status and valid URLs, indexed or excluded state and reason, organic impressions/clicks/CTR by cohort, mobile field CWV availability, and observed time and errors to reach feedback. Preserve the baseline before changing public content. |
| 15–42 | Give six useful lessons intent-specific titles and descriptions, add real prerequisite and next-skill links, and compare them with the six unchanged controls. | Review matched 28-day periods. Score snippet CTR only with at least 300 impressions in each cohort/window. Record impressions, clicks, CTR and position, plus whether selected canonicals remained stable. Extend the period when the sample is too small. |
| 43–70 | Add one original printable revision or teacher pack per syllabus case study and two short optional videos. Test links, A4 output and mobile layout before using each asset. | Compare Search Console clicks and engagement signals where available. In a consented walkthrough track whether participants reach the first checked answer, use the feedback, start independent practice and complete review. Report counts and denominators, plus print or video opens only if an approved measurement collects them. |
| 71–90 | Re-run the original sample and the six lesson pathways. Review which resources get found and which move learners to practice. | Publish the cohort comparison, measured completions over starts and availability of lab/field data. Keep variants that improve access without reducing accuracy or completion, and mark unresolved or low-volume tests inconclusive. |

Arena currently offers opted-in page views on its public homepage, course directory and library only. Those events cannot report lesson starts, response quality, completion or referrer queries. For the first round, use Search Console for search and structured, consented walkthroughs for learning. Define a start as opening the first checked task and completion as reaching its review conclusion after attempting the checks. If later an approved aggregate measurement becomes available, use separate counted events and report completion divided by starts, with cohort and device counts. Preserve the platform analytics boundaries for answers, student data, user identifiers, query strings and account routes.

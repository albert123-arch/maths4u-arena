# Maths4U

Единая образовательная платформа на базе существующего Arena. Next.js / TypeScript / Prisma / MySQL (MariaDB) / Tailwind / Zod. Обычный Node.js, без Redis, Docker и отдельных сервисов.

## Запуск в этой рабочей папке

1. Node.js 22 LTS, от 22.13.0 до 23; выполните `npm ci`.
2. Локальная MariaDB уже подготовлена в `.local/mariadb`, данные — `.local/mysql-data`, порт **33317**, привязка только к `127.0.0.1`. Запуск: `npm run db:local`. На новой машине положите Windows-дистрибутив MariaDB в `.local/mariadb`.
3. При первой установке выполните `node scripts/bootstrap-local.mjs`. Он создаёт только новые `maths4u_dev` и `maths4u_test`, отдельного пользователя и случайные пароли в игнорируемых `.env.local` и `.local/test.env`. Если конфигурация или базы уже существуют, скрипт отказывается их заменять. **В текущей папке этот шаг уже выполнен.**
4. `npm run db:migrate` применяет версионируемые миграции; `npx prisma migrate status` показывает состояние.
5. Создайте первого администратора способом ниже, затем `npm run prisma:seed` для трёх примеров и небольшого курса.
6. `npm run dev` → [локальная платформа](http://localhost:3000). Production-проверка: `npm run build`, затем `npm start`.

Для другой локальной MySQL создайте отдельную пустую базу с именем `maths4u_dev` или `maths4u_dev_*`, скопируйте `.env.example` в `.env.local` и задайте приватные реквизиты. `MATHS4U_DATABASE_NAME` должен в точности совпадать с базой в URL. Пароль в URL должен быть percent-encoded.

Старый `.env` не менялся и не используется для подключения к базе. Переменные `DATABASE_URL` и `DB_*` намеренно игнорируются. Во время разработки разрешены только loopback-хост и имена `maths4u_dev*` / `maths4u_test*`. Reset, drop и db push не выполнялись.

Для изменения схемы разработчиком `npm run prisma:migrate -- --name название` разрешён только на локальной `maths4u_dev*`; команда отклоняет production и тестовую базу. При установке зависимостей генерируется Prisma Client, без подключения к базе или миграций. Проверки, генерирующие Prisma Client или `.next`, запускайте последовательно.

## Первый администратор без пароля по умолчанию

Команда принимает приватные переменные `NEW_ADMIN_USERNAME`, `NEW_ADMIN_PASSWORD`, `NEW_ADMIN_NAME`. Пароль — минимум 10 символов, максимум 72 байта UTF-8. Не вводите пароль как литерал в командной строке с сохраняемой историей. Пример PowerShell:

~~~powershell
$env:NEW_ADMIN_USERNAME = Read-Host 'Логин администратора'
$env:NEW_ADMIN_NAME = Read-Host 'Имя администратора'
$adminSecurePassword = Read-Host 'Пароль (минимум 10 символов)' -AsSecureString
$env:NEW_ADMIN_PASSWORD = [System.Net.NetworkCredential]::new('', $adminSecurePassword).Password
try {
  npm run admin:create
} finally {
  Remove-Item Env:NEW_ADMIN_PASSWORD -ErrorAction SilentlyContinue
  Remove-Variable adminSecurePassword -ErrorAction SilentlyContinue
}
~~~

Команда не печатает пароль, не меняет существующих пользователей и прекращает работу, если администратор уже есть. Последующих учителей и администраторов назначают через кабинет управления. В рабочей базе разработки автоматически созданных администраторов и известных паролей нет.

Ученики регистрируются по логину и паролю без обязательной почты. При потере доступа администратор проверяет личность, нажимает «Восстановить доступ», передаёт одноразовый код лично. Ученик вводит его на `/recover`. Код действует час и используется один раз; сессии отзываются.

## Основные сценарии

Каталог по темам, набор учителя, самостоятельная практика и проверка вложений описаны в [инструкции по учебным сценариям](docs/LEARNING-UX.md). Порядок локальной проверки и выпуска исправления пилота — в [техническом отчёте](docs/UX-IMPLEMENTATION.md).

- `/teacher`: классы → QR/ссылка → задачи → назначить → проверить → опубликовать результаты → CSV.
- `/student`: задания, предыдущие попытки, комментарии, курсы и олимпиады.
- `/admin`: пользователи и несколько ролей, материалы, курсы, тарифы, выдача/отзыв доступа, импорт и состояние.
- `/library`, `/courses`: публичные разрешённые материалы. Практика требует входа, платный доступ проверяется отдельно.
- `/olympiads`: возрастная группа, тур по расписанию, сдача, проверка и публикация организатором.

Обычное ДЗ доступно ученику класса без подписки. Подписка не изменяет роли. Интерфейса оплаты нет.

## Проверки

~~~powershell
npm run typecheck
npm run lint
npm test
npm run test:ui
npm audit
~~~

`npm test` **действительно применяет миграции к отдельной тестовой MySQL**, затем проверяет API через Web Request/Response и настоящие транзакции. Обязательна `.local/test.env`; тест отказывается работать с другим типом имени или внешним хостом. Данные добавляются под случайными логинами, без очистки базы и без известных паролей.

`npm run test:ui` собирает production-приложение и запускает Playwright/Edge на `localhost:3100` с тестовой базой: регистрация → класс → назначение → автосохранение → перезагрузка → сдача → проверка → комментарий. Проверяются RU/EN, формулы, таблица, экран 390×844. Нужен Microsoft Edge; на другой машине поменяйте `channel` в `playwright.config.ts` или установите Chromium Playwright.

Скриншоты: `test-results/screenshots`. Сервер теста завершает себя через приватный сигнал `.local/ui-server.stop`, не оставляя фоновых процессов Windows. Отчёт: [docs/VERIFICATION.md](docs/VERIFICATION.md).

## Импорт

Администратор загружает JSON в `/admin/import` либо запускает:

~~~powershell
$env:IMPORT_ADMIN_USERNAME = Read-Host 'Логин существующего администратора'
npm run import -- fixtures/olymp.json
~~~

Лимиты: 100 записей и 2 МБ на файл. Источник + старый ID образуют уникальную пару; одинаковый импорт пропускается, изменённый создаёт новую редакцию. Нет подключений к старым базам и выполнения старого SQL. Форматы: [docs/IMPORT.md](docs/IMPORT.md).

Полный банк пяти курсов 0606 / 9231, локальный просмотр и пакет для Hostinger: [docs/FIVE-COURSE-IMPORT.md](docs/FIVE-COURSE-IMPORT.md). Каталог использует серверную пагинацию; перенос выполняется через защищённый административный импорт с dry-run и продолжением.

## Hostinger

Для Hostinger Business используются `npm run build` и запуск через `server.js`. Команда `build` вызывает тот же скрипт, что и `build:hostinger`, и создаёт `dist` без подключения к MySQL. HTTP-порт открывается сразу с ответом `503`; маршруты приложения включаются только после миграций, подготовки первого администратора и Next.js. npm-команды выполняет система развёртывания Hostinger, через SSH они недоступны.

Точные настройки для `https://arena.maths4u.sbs`, ветки `main`, приватных переменных и хранения файлов: [docs/HOSTINGER.md](docs/HOSTINGER.md). Приватные файлы должны находиться вне `hbuilds`, `public_html` и каталога сборки. Linux/Node.js 22 проверяется в GitHub Actions на `hostinger-preview` перед отправкой проверенного коммита в `main`. Результат CI не заменяет проверку реального деплоя, удалённой базы и сохранности файлов на Hostinger.

## Границы первой версии

Работают аккаунты и сессии, классы, курсы/теория, RU/EN, банк и редактор задач с частями, неизменяемые опубликованные задания, практика, таймер, автосохранение, приватные фото/PDF, автоматическая и ручная проверка, олимпиады, ручная выдача подписок, лимиты практики и импорт.

Отложены: реальные платежи/webhook, AI-проверка, расширение переноса за пределы пяти выбранных курсов, email-рассылки, автоматическое подтверждение возраста, редактор нескольких туров/групп, игровые режимы с ведущим и бонусы скорости. Схема допускает эти расширения. Банк задач использует серверную пагинацию по 25 записей (до 50 на страницу).

История не зависит от подписки. Архивирование сохраняет пользователей, классные связи, задания, попытки и оценки; важные связи защищены внешними ключами.

Архитектура: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).
